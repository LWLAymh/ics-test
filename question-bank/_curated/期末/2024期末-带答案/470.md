第三题（15分）
Part A: 分析下面这段代码的行为，假设file.txt文件存在，且不需要考虑
open()函数未能正常打开文件的情况。
```
#include <csapp.h>
int main(){
    int fd[3];
    fd[0] = open("./file.txt", O_RDWR | O_TRUNC, 0);
    fd[1] = open("./file.txt", O_RDWR | O_TRUNC, 0);
write(fd[0], "Harry", 5);
if (fork() == 0) {
    dup2(fd[0], fd[1]);
    write(fd[1], "Voldemort", 9);
    fd[2] = open("./file.txt", O_RDWR, 0);
    printf("%d\n", fd[2]);
    exit(0);
}
wait(NULL);
fd[1] = dup(fd[0]);
write(fd[0], "Hermione", 8);
write(fd[1], "Ron", 3);
fd[2] = open("./file.txt", O_RDWR, 0);
printf("%d\n", fd[2]);
}
```
1） 运行这段代码，在终端上可以看到两行输出，第一行的内容为          ，
第二行的内容为          。(每空1分)
2） 运行这段代码后，file.txt文件的内容为                             。
（3分）
%%% answer
答案（原卷自带参考答案，见本卷「参考答案 Part A」）：
1）第一行：`5`；第二行：`6`
2）file.txt 的内容为：`HarryVoldemortHermioneRon`

解析：
**1）两行输出都是 `open()` 返回的描述符编号**（`printf("%d\n", fd[2])`）。
进程启动时描述符 0/1/2 已被占用，所以：
- 父进程：`fd[0] = open(...)` ⇒ 3；`fd[1] = open(...)` ⇒ 4。
  子进程里 `dup2(fd[0], fd[1])` 把 fd[1]（= 4）重新指向 fd[0] 所指的打开文件，
  **不占用新的描述符**，所以随后 `fd[2] = open(...)` 拿到 **5** ⇒ 第一行 `5`。
- 父进程 `wait(NULL)` 之后执行 `fd[1] = dup(fd[0])`：`dup` 返回**当前最小可用
  描述符**。此时 3 被 fd[0] 占用、4 仍然被原来的 fd[1]（未被关闭）占用，
  所以 dup 返回 **5**，fd[1] 变成 5；接着 `fd[2] = open(...)` 只能拿到 **6**
  ⇒ 第二行 `6`。

**2）文件内容：`HarryVoldemortHermioneRon`。**
关键点：`fork`、`dup`、`dup2` **都不会创建新文件**，所有写操作最终都落到同一个
`file.txt` 上，因此内容就是各次写按发生顺序拼接：
- 父进程先 `write(fd[0], "Harry", 5)`；
- 子进程 `dup2(fd[0], fd[1])` 后 `write(fd[1], "Voldemort", 9)` —— 由于 fd[1]
  与 fd[0] 指向**同一个打开文件表项**（由 `dup2` 造成），文件偏移是共享的，
  所以 `Voldemort` 紧接在 `Harry` 之后；
- 子进程 `exit(0)` 后父进程的 `wait(NULL)` 返回，父进程写 `Hermione`、再写 `Ron`，
  二者也共享同一个打开文件表项（`dup` 的结果），顺序拼接。
⇒ `Harry` + `Voldemort` + `Hermione` + `Ron` = `HarryVoldemortHermioneRon`。
