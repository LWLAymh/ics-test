答案：（1 每空1分共6分；2 每空1分共4分）
(1) 
| 协议层次 | 协议名称 | 是面向连接的吗？ |
| --- | --- | --- |
| 网络层 | IP | 否 |
| 应用层 | HTTP | 否 |
| 传输层 | TCP | 是 |

(2) 
1：`bind`
2：`listen`
3：`connect`
4：`rio_readlineb`
（对照原卷配图：服务器端 `socket → 1 → 2 → accept`，客户端 `socket → 3 → Connection request`，
`connect` 后客户端先 `rio_writen` 发请求、再 `rio_readlineb` 收应答；服务器端回完数据后
客户端 `close` 发出 EOF，服务器端读到 EOF 在标号 4 处跳出读循环，然后 `close`。）

解析：
**1. 协议栈三行表。**
- 网络层：可选的协议名只有 IP（UDP/TCP/HTTP 都在别的层），IP 是**无连接**的
  「尽力而为」数据报服务，不保证顺序 ⇒ 否。
- HTTP 是**应用层**协议（Web 应用协议），它建立在 TCP 之上，但 HTTP 自身
  不是面向连接的协议 —— 题目说明「面向连接的协议保障数据按照发送时的顺序
  被接收」，HTTP 消息本身不提供这种保证（顺序由下面的 TCP 保证）⇒ 否。
- TCP 是**传输层**协议，三次握手建立连接、按序号确认重传 ⇒ 是。
（干扰项 UDP 也是传输层，但它是无连接的，本题表格里没有它的位置。）

**2. 套接字流程填空。**
服务器端顺序是 `socket → bind → listen → accept`，
客户端是 `socket → connect`。图中：
1 = 服务器把自己的地址/端口绑定到套接字上 ⇒ **bind**；
2 = 把主动套接字变成监听套接字，开始接收连接请求 ⇒ **listen**；
3 = 客户端发起三次握手，建立到服务器的连接 ⇒ **connect**；
4 = 客户端/服务器读一行数据的 RIO 函数 ⇒ **rio_readlineb**
（对应的还有 `Rio_writen`，图中这一处是读方向）。
