原卷在每个小问之后直接印出了答案，下面是整理后的原卷答案与推导。

**1．（1 分）最多再监听多少个连接。**
原卷答案：`4*216 – 4`（原文转写把指数 2¹⁶ 写成了 216），即 **4 × 2¹⁶ − 4 = 262140**。
一条 TCP 连接由四元组 `(客户端 IP, 客户端端口, 服务器 IP, 服务器端口)` 唯一确定：
- 服务器有 4 个独立固定 IP，任选其一进入四元组 ⇒ 4 种；
- 服务器端口固定为 web 端口 80；
- 客户端只有一个固定 IP，只有它的 16 位端口号可变 ⇒ 2¹⁶ 种；
- 但每个服务器 IP 上的 80 端口本身已被监听套接字（`listenfd`）占用，故每个 IP 减 1。
原卷另附更保守的口径「（4×2¹⁶ − 4×well-known 端口数）」，即连客户端的知名端口也不许用。

**2．（2 分）socket pair 错在哪。**
- 客户端 IP：`192.168.100.121` 是 NAT 后面的**内网地址**，不能出现在连接四元组里，
  应写参与连接的公网地址 **162.105.192.178**；
- 服务器端口：HTTP 服务器默认监听 **80**，题中写的 25 是 SMTP 的端口。
  （原卷答案：`192.168.100.121不对，原因：不能用内网IP；25应该是80，原因：网页浏览器应用的默认监听端口是80端口。`）

**3．（4 分）Echo Server 的交互箭头。**
| 步骤 | 方向 | 对应代码 |
| --- | --- | --- |
| 建立连接 | client → server | `clientfd = Open_clientfd(host, port)` ⇒ `connfd = Accept(listenfd, …)` |
| 发送请求 | client → server | `Rio_writen(clientfd, buf, strlen(buf))` ⇒ `while((n = Rio_readlineb(&rio, buf, MAXLINE)) != 0)` |
| 接收应答 | server → client | `Rio_writen(connfd, buf, n)` ⇒ `Rio_readlineb(&rio, buf, MAXLINE)` |
| 关闭连接 | client → server | `Close(clientfd)` ⇒ `Close(connfd)` |

（原卷在同一代码块上用 `--------à` / `ß-----------` 标出了这四条单向箭头。）

**4．（3 分）Tiny Server。**
a. **filename** —— `Execve(filename, emptylist, environ)` 把它当作要运行的程序路径。
b. **动态** —— 走的是 CGI 分支（`setenv("QUERY_STRING", …)` + `Dup2(fd, STDOUT_FILENO)` + `Execve`），
   内容由 `filename` 这个程序在运行时生成；静态内容则直接由 `rio_readn`/`mmap` 把磁盘文件送回。
c. 需要加入**并发处理能力** —— 对每个 `Accept` 返回的 `connfd` fork 子进程、开线程，
   或用 I/O 多路复用（select/poll/epoll）在单进程内轮转。
   （原卷答案：`可以通过多进程、多线程或IO多路复用进行更改`。）
