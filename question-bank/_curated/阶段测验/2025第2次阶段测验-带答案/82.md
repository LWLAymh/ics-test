5. （8分）Y86-64 的 `popq rA` 指令编码为 `b 0 rA 8`。根据 popq 指令的操作，补全下表（共需填 8 行 9 空）：

| 阶段 | 计算（popq rA） |
| --- | --- |
| Fetch | `icode:ifun ← M1[PC]`（已给） |
|  | `rA:rB ← M1[{{blank:q5-fetch-address}}]` |
|  | `valP ← PC+2`（已给） |
| Decode | `valA ← R[{{blank:q5-src-a}}]` |
|  | `valB ← R[{{blank:q5-src-b}}]` |
| Execute | `valE ← {{blank:q5-alu-a}} + {{blank:q5-alu-b}}` |
| Memory | `{{blank:q5-memory-result}} ← M8[valA]` |
| Write back | `R[{{blank:q5-dst-e}}] ← valE` |
|  | `R[{{blank:q5-dst-m}}] ← valM` |
| PC update | `PC ← {{blank:q5-next-pc}}` |
%%% answer
答案（8 行 9 空，按表格自上而下逐空填写）：

① `PC+1`　② `%rsp`　③ `%rsp`　④ `valB`　⑤ `8`　⑥ `valM`　⑦ `%rsp`　⑧ `rA`　⑨ `valP`

补全后的表：

```text
阶段          计算（popq rA）
Fetch         icode:ifun ← M1[PC]          （已给）
              rA:rB ← M1[PC+1]
              valP ← PC+2                  （已给）
Decode        valA ← R[%rsp]
              valB ← R[%rsp]
Execute       valE ← valB + 8
Memory        valM ← M8[valA]
Write back    R[%rsp] ← valE
              R[rA] ← valM
PC update     PC ← valP
```

解析：

1. 指令编码：题面给出 popq rA 的字节序列为 `b 0 rA 8`，即第 1 字节 `icode:ifun = b:0`、第 2 字节 `rA:rB`（其中 `rB` 不用）、第 3 字节是功能码 8。popq 没有立即数/偏移量，所以指令长度固定 2 字节（icode:ifun 与 rA:rB）。
2. **Fetch**：按 SEQ 的取指规则，先取指令第 1 字节放到 `icode:ifun`，再把下一个字节取到 `rA:rB`，于是空填 `PC+1`；同时 `valP = PC + 2`（已给），指向下一条指令。
3. **Decode**：popq 需要「从栈顶取数」并且「把栈指针加 8」，这两件事都要用到老的 `%rsp`。SEQ 的寄存器堆只有 2 个读端口，所以 srcA 与 srcB **都读 `%rsp`**：`valA ← R[%rsp]`（后面当访存地址用）、`valB ← R[%rsp]`（后面当 ALU 操作数用）。
4. **Execute**：`valE ← valB + 8`，即老栈指针加 8，得到新的 `%rsp`（ALU 做加法；题面写成 `valB + 8`，与 HCL 里 `aluA = 8, aluB = valB` 的加法可交换，等价）。
5. **Memory**：`valM ← M8[valA]`，用 `valA`（老 `%rsp`）作地址从内存读出被弹出的 8 字节。
6. **Write back**：SEQ 的寄存器堆有 2 个写端口，这一阶段同时写两个目的寄存器 —— `R[%rsp] ← valE`（更新栈指针）和 `R[rA] ← valM`（把弹出的值写入 `rA`）。注意 `%rsp` 用的是 `valE`（加 8 之后的值），`rA` 用的是 `valM`（内存读出的值），两者不能互换。
7. **PC update**：`PC ← valP`，顺序取下一条指令。
