%%% stem
第七题（10 分）

如下是使用 C 语言描述的链表结构的声明，链表的结尾使用空指针来表示。同时使用函数 `int length (List *p)` 来计算链表的长度。为简化起见，假设该链表是非循环的。

```c
typedef struct LIST {
    struct LIST *next;
    int data;
} List;
```

函数 `count_pos1` 的目标是计算链表中 `data` 为正数的元素个数，并将结果写到 `k`。下面是有待分析的原始程序，供三个小问共同参考：

```c
void count_pos1 (List *p, int *k) {
    int i;
    for (i = 0; i < length(p); i++) {
        if (p->data > 0)
            *k++;
        p = p->next;
    }
}
```
%%% reference

%%% part-stem: q-ba2c74807aaa6642
1）指出公共代码中导致效率低或结果错误的问题，并修改程序。（4分）
%%% part-reference: q-ba2c74807aaa6642
原程序每轮调用 `length(p)`，产生二次复杂度；而且 `p` 每次向后移动，使 `length(p)` 越来越小，循环条件还会导致后半段未被遍历。`*k++` 实际递增指针，不是对计数加一；也不应依赖 `*k` 先前已有的值。下面先固定长度、用局部计数器累计，最后一次写回：
```c
void count_pos1 (List *p, int *k) {
    int i, num=0, len;
    len = length(p);
    for (i = 0; i < len; i++) {
        if (p->data > 0)
            num++;
        p = p->next;
    }
    *k = num;
}
```
%%% part-stem: q-183f85f12346b2b9
2）为提高程序性能，可以考虑删除变量 i 以消除函数调用。请修改上述程序达到该目的。（2 分）
%%% part-reference: q-183f85f12346b2b9
例如：

```c
void count_pos2(List *p, int *k) {
    int num = 0;
    while (p) {
        if (p->data > 0)
            num++;
        p = p->next;
    }
    *k = num;
}
```

该实现不再调用 `length`，也无需下标 `i`，遍历一次即可。
%%% part-stem: q-98eb3da0dc90d60f
3）上述程序内层循环的汇编片段如下所示。假设该链表不为空且大部分数据都为正数，转移预测全部正确，设计中有足够多的部件来实现指令并行。其中访存操作全部 cache 命中，时延为 3 cycle，其他指令时延为 1cycle。请计算以下程序的 CPE 下限，并给出文字说明。（4 分）

```asm
.L1:
    movl   4(%eax), %ecx
    testl      %ecx, %ecx
    jle    .L2
    incl       %edx
.L2:
    movl   (%eax), %eax
    testl  %eax, %eax
    jne    .L1
```
%%% part-reference: q-98eb3da0dc90d60f
按题目给出的理想并行和预测全对条件，关键循环携带依赖是：本轮 `movl (%eax),%eax` 得到下一结点指针，下一轮访存才能使用它。加载延迟为3周期，所以该指针追踪链给出的CPE下限为 **3周期/结点**。读取 `data`、计数和预测正确的控制流可与指针加载重叠，不必把后面的 `test` 再固定串行增加1周期。

原卷答案写 `3+1=4`，这只适用于额外要求下一轮访存必须等待非空测试完成的串行估算；该限制与本题已允许的理想指令并行／预测条件并不等同。此处记录勘误，仍保留要求解释依赖链的简答，不把实际硬件吞吐率保证为恰好3。
