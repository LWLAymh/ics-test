第四题（10分） 链接
考虑如下3个文件：`main.c, fib.c`和`bignat.c`：
假设所需标准头文件和函数原型已正确声明（片段中省略），命令行参数有效，静态库按从左到右的一遍扫描处理。

```c
/* main.c */
void fib (int n);
int main (int argc, char** argv) {
    int n = 0;
    sscanf(argv[1], "%d", &n);
    fib(n);
}
/* fib.c */
#define N 16
static unsigned int ring[3][N];
static void print_bignat(unsigned int* a) {
    int i;
    for (i = N-1; i >= 0; i--)
        printf("%u ", a[i]); /* print a[i] as unsigned int */
    printf("\n");
}
void fib (int n) {
    int i, carry;
    from_int(N, 0, ring[0]); /* fib(0) = 0 */
    from_int(N, 1, ring[1]); /* fib(1) = 1 */
    for (i = 0; i <= n-2; i++) {
        carry  =  plus(N,  ring[i%3],  ring[(i+1)%3],
            ring[(i+2)%3]);
        if (carry) {
            printf("Overflow  at  fib(%d)\n",  i+2);
            exit(0);
        }
    }
    print_bignat(ring[n%3]);
}
```
另外，假设在文件`bignat.c`中定义了如下两个函数`plus`和`from_int`（具体
定义略）：


```c
int plus (int n, unsigned int* a, unsigned int* b, unsigned int* c);
void from_int (int n, unsigned int k, unsigned int* a);
```

%%% part-reference: signed-ring-explanation
更正原答案的绝对表述：`int *` 与 `unsigned int *` 不是兼容指针类型。完整原型可见时，把 `ring[i]` 传给这些函数会产生不兼容指针类型的诊断；开启将诊断视为错误的编译选项可能导致编译失败。

如果实现接受该程序，则 ELF 链接器通常不检查这些 C 类型，符号绑定和存储大小不变。课程所用 `int` 与 `unsigned int` 同宽，且通过对应的无符号整数类型访问对象表示有特殊许可，因此原程序的无符号运算可得到相同位级结果。但不能据此说“对编译没有影响”，也不能推广为任意不兼容指针都安全。
