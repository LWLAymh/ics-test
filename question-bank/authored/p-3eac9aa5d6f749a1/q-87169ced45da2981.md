### 8.3 缓冲区攻击（8 分）

考虑以下 C 语言程序：

```c
void read_input(void) {
    char buf[16];
    gets(buf);  // gets() 是本课程所讲授的有安全隐患的函数
}

void process(void) {
    read_input();
    /* 后续操作 */
}
```

在一台 x86-64 Linux 计算机上，`read_input` 对应的 AT&T 汇编代码如下：

```asm
read_input:
    subq $40, %rsp
    leaq 8(%rsp), %rdi
    call gets
    addq $40, %rsp
    ret
```

已知以下条件：

- 调用 `read_input` 时，`call` 指令的下一条指令地址为 `0x4012A5`。
- 刚进入 `read_input` 时，`%rsp = 0x1208`。
- 程序未启用“栈金丝雀”。
- `gets` 读取输入的所有字符，并在末尾添加 `\0` 字符。
- 假设下面讨论的越界写入不会引起系统的其他异常情况处理操作，按给定汇编布局分析。

回答以下问题：

1. `gets` 执行时，数组 `buf[0]` 的内存地址为（十六进制，可省略 `0x`）：{{blank:buffer}}（2 分）
2. 假设用户只输入连续的字符 `A`（ASCII 码为 `0x41`），随后按回车。若要求输入不会修改返回地址，最多可以输入多少个字符 `A`？{{blank:maximum}}（2 分）
3. 按照第（2）问的情况，如果再多输入 1 个字符 `A`，那么 `read_input` 执行 `ret` 时将跳转到哪个地址？用十六进制表示：{{blank:target}}（2 分）
4. 如果程序启用“栈金丝雀”，是否可以阻止返回地址被修改？{{blank:canary}}（2 分）

第四问的“阻止被修改”指阻止越界写入本身，而不是检测到修改后在返回前终止程序。

各空依次为 `0x11E8`、`31`、`0x401200`、否。

以下栈布局推导为录入时的补充解释；判分答案与随卷参考一致：

| 位置 | 地址或偏移 |
| --- | --- |
| 刚进入 `read_input` 时的 `%rsp`（保存返回地址处） | `0x1208` |
| 减去 40 字节后的 `%rsp` | `0x11E0` |
| `buf[0]`（`8(%rsp)`） | `0x11E8` |
| 保存返回地址的起始地址 | `0x1208` |
| 从 `buf[0]` 到返回地址的距离 | `32` 字节 |

输入 `31` 个 `A` 时，末尾的 `\0` 写到 `0x1207`，不触碰返回地址。输入 `32` 个 `A` 时，`\0` 写到 `0x1208`。x86-64 采用小端序，因此返回地址 `0x4012A5` 的最低字节从 `0xA5` 变为 `0x00`，`ret` 跳转到 `0x401200`。

栈金丝雀用于检测部分越界写入，通常在返回前发现标记异常并终止程序；它不阻止越界写入实际发生，也不保证返回地址本身不会被写改。
