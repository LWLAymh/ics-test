参考实现之一（N=3、M=5；用临时变量明确反汇编的求值顺序）：

1、答案：
```c
#define N   3
#define M   5
struct P1 {char c[N]; char *d[N]; char e[N]; } P1;
struct P2 {int i[M]; char j[M]; short k[M]; } P2;
unsigned int f(unsigned int n)
{
    static unsigned int x = sizeof(P1);
    static unsigned int y = sizeof(P2);
    if (n<=1)
        return 1;
    if ((n & 1) == 0)
        x++;
    if ((n & 1) == 1)
        y++;
    unsigned int r = f(n - 1);
    return r + y + x;
}
```
第二问原卷给 `4f, 4e`，并将 `4e, 4f` 标成半分；下述勘误说明题库为何对两者均判对。

题库勘误：第一部分只推出 `sizeof(P1)+sizeof(P2)=76`，正整数解为 `(N,M)=(1,7),(2,6),(3,5),(4,4)`，不是只有原答案3,5。反汇编中在递归返回后才读取静态x/y；普通C表达式 `f(n-1)+y+x` 本身没有强制这种操作数求值次序，故题面模板用临时变量 `r` 明确顺序。

第二段程序的两个函数实参求值先后顺序没有被C语言固定。独立从初始状态运行时，两次返回值依次为 `0x4e` 和 `0x4f`，但打印顺序可以是 `4e, 4f` 或 `4f, 4e`，题库两者均判对，不沿用原卷把其中一种只给半分的规则。
