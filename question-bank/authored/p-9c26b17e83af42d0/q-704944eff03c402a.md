### 13.4（5 分）

某数据 Cache 有 2 组、每组 2 行、每块 8 字节，使用中间地址位作组索引。采用 LRU 替换、写分配（write-allocate）和写回（write-back）。初始所有行均无效；读写命中都会更新 LRU 次序，新装入块视为最近使用。

LRU（Least Recently Used，最近最少使用）替换策略：当 Cache 某组已满且需要替换时，淘汰该组中最长时间未被访问的缓存行。

按下列顺序访问，每次只读或写 1 个字节，地址均为十进制；`W` 表示一次普通的字节写入。只统计此序列，没有其他访问，也不在序列结束时主动清空 Cache。

```text
R 0, W 1, R 16, R 8, R 0, W 32, R 16, R 40
```

以下均填十进制数，每空 1 分：

1. 8 次 CPU 访问共发生 {{blank:misses}} 次未命中。
2. 因替换脏（dirty）块而向主存写回整块数据，共发生 {{blank:writebacks}} 次。
3. 序列结束时，第 0 组中保留的两个主存块，其起始地址按从小到大为 {{blank:low}}、{{blank:high}}。
4. 序列结束时，第 0 组中的脏块，其主存起始地址为 {{blank:dirty}}。
%%% reference
五空依次为 `6`、`1`、`16`、`32`、`32`。

访问结果依次为 `M、H、M、M、H、M、M、M`。`W 32` 替换的是干净块 `[16, 23]`；随后 `R 16` 替换脏块 `[0, 7]`，发生唯一一次写回。最后第 0 组保留 `[16, 23]`（干净）与 `[32, 39]`（脏）。最后 `R 40` 属于第 1 组，不改变第 0 组状态。
