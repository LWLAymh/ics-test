### 16.3（4 分）

某父进程已安装 `SIGCHLD` 信号处理函数，并阻塞了 `SIGCHLD`。该父进程共有 3 个子进程。在解除阻塞前，3 个子进程均已终止，相应的 `SIGCHLD` 均已产生，但父进程尚未调用 `wait` 或 `waitpid`，也未启用自动回收。

考虑以下两种不同的信号处理函数（两种方案分别独立执行，初始条件完全相同）。

方案 A：

```c
void handler(int sig) {
    waitpid(-1, NULL, 0);
}
```

方案 B：

```c
void handler(int sig) {
    while (waitpid(-1, NULL, 0) > 0)
        ;
}
```

父进程解除 `SIGCHLD` 阻塞。假设此后没有新的子进程状态变化，也没有其他相关信号或系统调用错误。只讨论课件中的普通信号。

1. 解除阻塞前，父进程的 `pending` 向量中，`SIGCHLD` 对应位的数值为 {{blank:pending}}。（1 分）
2. 方案 A 的处理函数执行结束后，仍有 {{blank:zombies}} 个已终止但尚未被回收的子进程。（1 分）
3. 方案 B 的处理函数中，`waitpid` 返回正 PID 的次数为 {{blank:positive}}。（1 分）
4. 方案 B 的处理函数中，`waitpid` 总共被调用 {{blank:calls}} 次。（1 分）
%%% reference
四空依次为 `1`、`2`、`3`、`4`。

三个 `SIGCHLD` 发生时均处于阻塞状态，同类普通信号不排队，因此只保留一个 pending 标记。解除阻塞后，该未决信号触发一次处理函数调用。方案 A 只回收一个子进程，另外两个仍处于僵尸状态。

方案 B 通过循环依次成功回收三个子进程。三次成功回收之后，第四次 `waitpid` 返回 `-1`（`errno = ECHILD`），循环终止，所以正 PID 返回 3 次、调用总数为 4 次。
