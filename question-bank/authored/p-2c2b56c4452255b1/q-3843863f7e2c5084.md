第五题 虚拟内存

前两问共用下面的IA32地址翻译数据；第3问另按64位Linux解释。访问计数只考虑所列地址的一次数据访问，忽略预取和其他缓存内容。

IA32体系采用小端法、32位虚拟地址和两级页表。两级页表大小相同，页大小
都是 4 KB = $2^{12}$ Byte，结构也相同。TLB 采用直接映射，4 位组索引。TLB
和页表每一项格式如下：

| 位 | 31-12 | 11-9 | 8 | 7 | 6 | 5 | 4 | 3 | 2 | 1 | 0 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 字段 | 4 KB 页框地址 | 忽略 | G | PAT | D | A | PCD | PWT | U/S | R/W | P |

部分位的含义如下：
0 (P): 1表示存在，0表示不存在
1 (R/W)：1表示可写，0表示只读
2 (U/S)：0表示仅允许内核/超级用户访问；1表示允许用户模式访问（内核也可访问）。

> 原卷勘误：U/S的0/1含义写反了，这里按真实IA32修正，因此相关权限答案随之修正。内存表中误印的地址 `00e66d07` 改为 `00e66007`；教师分章节题目稿也写作后者，才能给出页目录项的完整4字节。

当系统运行到某一时刻，TLB有效位为1的条目如下（未列出部分都是无效的）：

| 索引（十进制） | TLB 标记 | 内容 |
| --- | --- | --- |
| 0 | `0x0400` | `0x0ec91313` |
| 3 | `0x02ff` | `0x5d2bac01` |
| 5 | `0xd551` | `0x019fa42d` |
| 11 | `0x55a6` | `0xfdd3c66b` |
| 13 | `0x5515` | `0xb591926b` |

一级页表基地址为`0x00e66000`，物理内存中的部分内容如下（均为十六进制）：

| `00615003` | `c0` | `006154d0` | `ff` | `006154d1` | `a0` |
| `00e66001` | `a1` | `00e66002` | `a4` | `00e66003` | `67` |
| `00e66004` | `21` | `00e66005` | `57` | `00e66006` | `61` |
| `00e66007` | `00` | `2167e000` | `42` | `2167e001` | `67` |

异常，这一过程中，需要访问物理内存 {{blank:q5-1-memory-accesses}} 次（3分）。具体来说，如果该地址
为 `y = 0xd5515213`，y 地址所具有的实质权限是 {{blank:q5-1-permissions}}（多选题，选
对才得分2分）。
①可写 ②只读 ③用户模式权限  ④内核模式权限
%%% part-reference: q-64ab5fa1b609de6b
答案：
需要访问物理内存 1 次（TLB 命中且无缺页，只需访问一次物理页）。
按勘误后的真实IA32位义，`y = 0xd5515213` 的权限为 **②③（只读、允许用户模式访问）**。VPN为 `0xd5515`，低4位索引为5、TLB标记为 `0xd551`，命中条目 `0x019fa42d`；其R/W位为0，U/S位为1。

原答案②④依赖题面颠倒的U/S定义，不能在修正位义后继续作为判分键。TLB保存完整有效翻译，本问不额外访问页目录或页表。

%%% part-reference: q-a71284ceb71900f9
答案：

`x = 0x004004d0` 对应的二级页表起始地址是 `0x00615000`，x 地址上单字节的内容是 `0x48`。

页目录索引1、二级索引0、页内偏移 `0x4d0`。页目录项在 `0x00e66004`，4字节按小端读得 `0x00615721`；其页框为 `0x00615000`。该处PTE为 `0xc0ee2d21`，物理页框 `0xc0ee2000`，目标字节地址为 `0xc0ee24d0`，给定内容 `0x48`。
%%% part-stem: q-af42836a7c424fe9
3. 考虑下面计算矩阵和向量乘法代码：
```
1 int *mat_vec_mul(int **A, int *x, int n)
2 {
3     int i, j;
4     int *y = (int *)malloc(n * sizeof(int));
5     for (i = 0; i < n; i++)
6         for (j = 0; j < n; j++)
7             y[i] += A[i][j] * x[j];
8     return y;
9 }
```
⑴ 在64位 Linux 机器中运行该代码，输入同一组合法的参数后，每次运行
返回的向量值可能受未初始化内存影响。修复这一错误，可将第 {{blank:q5-3-line}} 行改为
{{blank:q5-3-fix-code}}。（第二空填写C代码，每空1分，共2分）
请保留 `int *y` 声明，用 `calloc` 或课程封装 `Calloc`，两个参数依次填写元素数 `n` 和单元素大小 `sizeof(int)`；完整语句含分号。
可能用到的函数：
```
void *memcpy(void *dest, const void *src, size_t n);
void *memset(void *s, int c, size_t n);
void *calloc(size_t nelem, size_t elemsize);
void *realloc(void *ptr, size_t size);
```
⑵ 在进行前一问的测试之前，还在64位 Linux 机器上进行过如下用户代码
测试（输入 `mat_vec_mul`的参数都非零）：
```
int *y = mat_vec_mul(A, x, n);
int z = y[0];
```
结果在读取 `y[0]` 时发生段错误，但函数内部没有发生段错误。设 `int` 为32位、`size_t` 为64位，本题分配器拒绝大于等于 $2^{63}$ 字节的单个请求并返回NULL；排除并发释放和映射改变等其他原因。给出一种 `n` 的取值条件，解释它如何导致分配失败、跳过循环并在函数外访问NULL：{{blank:q5-3-segfault-condition}}。（解释自评，1分；不再声称未限定的任意环境下有单一“充要条件”。）
%%% part-reference: q-af42836a7c424fe9
答案：
⑴ 第4行改为 `int *y = (int *)calloc(n, sizeof(int));`。`calloc` 清零所分配区域，消除对未初始化 `y[i]` 的累加。题面已规定参数顺序，代码内空白不影响核对。

⑵ 例如 `n=-1`，或一般的 `n<0`：按给定类型计算，负数转换为 `size_t` 后参与乘法，得到接近 $2^{64}$ 的巨大请求，超过本题分配上限而返回NULL；`i=0` 不满足 `i<n`，两重循环不进入，函数直接返回NULL，外部 `y[0]` 因而非法。这里说明的是题面模型下的一种完整因果链，不将原参考中的 `n<0` 无条件推广为所有系统异常的唯一原因。
%%% part-stem: q-c470de9f3073d787
4. Double fault：处理器在递送某些异常时又遇到特定异常，无法完成原异常的递送，可能产生double fault（双重故障）。这不等于“处理程序中发生任何新故障都会双重故障”：正常嵌套异常可以分别处理。假设除了缺页异常的递送/处理路径外，其他异常处理路径都不会引发新故障。如果某次缺页最终造成无法正常递送缺页异常的double fault，其原因可能是：（不定项选择，都选对才得分，1分）

答案：C（原卷选项③）。

缺页处理程序自身不驻留时，可能在取指/递送路径中反复缺页，使处理无法继续；例如递归消耗异常栈后再次无法递送。C问的是可能原因，不是说处理程序一次取指缺页必然立即双重故障。A中U/S=0允许内核执行，不构成该权限错误；普通键盘中断也不单独导致双重故障。原卷对double fault的笼统定义已澄清。
%%% part-option: q-c470de9f3073d787 A
运行缺页故障处理程序时，CPU 上的权限位是内核态，但所执行代码段 `U/S=0`。
%%% part-option: q-c470de9f3073d787 B
运行缺页故障处理程序时，CPU 接收到了键盘发送的 Ctrl+C 信号。
%%% part-option: q-c470de9f3073d787 C
缺页故障处理程序没有加载到主存中。
