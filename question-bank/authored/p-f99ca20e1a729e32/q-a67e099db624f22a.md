%%% stem
8.  文件`f1.c`和`f2.c`的C源代码如下图所示：

```c
//f1.c
#include<stdio.h>
extern float x;
extern void f();
int main()
{
   f();
   printf("%d\n",(int)x);
   return 0;
}
```

```c
//f2.c
int x = 0;
void f()
{
   x++;
}
```

已知这两个文件在同一个目录下，在常规Linux/x86-64的32位int/IEEE binary32环境，用 `gcc -Og -o f f1.c f2.c` 分离编译链接，不启用LTO或跨文件类型检查。按原卷机器位表示模型分析：忽略跨文件不兼容声明的ISO C未定义行为，`f2.c` 按int访问x，`f1.c` 按float读取同一4字节存储。运行 `./f` 会出现：
%%% reference
答案：B（来源：2019、2020期末-答案解析）
解析：在给定分离编译模型下，链接器不据符号表检查C类型。`f2.c` 的 `x++` 是整数自增，把存储改为 `0x00000001`；`f1.c` 将该位型读为最小正binary32非规格化数，转换为int得到0。原解析将整数自增误说成浮点自增，已纠正。
