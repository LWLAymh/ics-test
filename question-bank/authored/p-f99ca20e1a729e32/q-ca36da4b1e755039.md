1. 火锅洞洞主终于要请吃火锅啦！由于防疫规定，洞主决定分批邀请，Alice、
Bob、……、Zach这26位同学顺理成章地成为了第一批受到邀请的同学。他们围坐在
一张圆桌旁，按照首字母顺序排列（即Alice的右边是Bob，Bob的右边是
Carol，……，Zach的右边是Alice）。吃饭之前，洞主想要验证他们的身份，他提出了
这样的要求：

1） 每位同学有一个编号，即字母序号减1，也就是说，Alice是0号，Bob是1
号，以此类推。

2） 每位同学需要同时拿着旁边两位同学的手机去找洞主（不必带上自己的手
机），按照洞主的要求在树洞里发信息以验证身份。

3） 可以同时有多位同学找洞主验证（也就是说，Alice需要拿着Zach和Bob的
手机找洞主，并且在同一时间，Bob也可以拿着Alice和Carol的手机找洞
主。但是，如果Alice还没同时拿到Zach和Bob的手机，就只能坐在座位上
等待。）

%%% reference
### 1.1

死锁。26 人并发时可能形成两个环形等待链，例如偶数编号线程分别先占有所有奇数编号的信号量，再等待另一个已占用的奇数编号信号量。

### 1.2

例如 `P(&sem[0])`、`V(&sem[0])`。任何所有线程共同使用的固定下标 `0` 至 `25` 都可以，但两处必须相同；输入框共享同一答案。

### 1.3

A = ①，B = ②，C = ②，D = ①，即 `1, 2, 2, 1`。这对应题面指定的先锁较小编号、再锁较大编号，破坏循环等待。

原参考也允许全体统一采用相反顺序，但不能让每个空独立任选 ① 或 ②，否则会接受产生死锁的组合。本版明确要求递增顺序，以便逐空自动核对。

| 空位 | 答案 |

| A | `1` |
| B | `0` |
| C | `<` |

`mutex` 用于保护 `value`，初值为 1；`zero` 是等待信号量，初值为 0。`value--` 后若小于 0，本次 P 需释放互斥锁再等待；`value++` 后若小于等于 0，则需唤醒等待者。
