练习题 11.5：图 11-27 的 CGI 程序由服务器创建的子进程运行，通过标准输出返回 HTTP 响应，末尾的相关代码如下（`content` 为已生成的响应正文）：

```c
printf("%s", content);
fflush(stdout);
exit(0);
```

第 10.11 节提醒过在网络应用中使用 C 标准 I/O 的风险。为什么这种每次请求运行一个 CGI 子进程的用法仍然可行？
%%% reference
来源参考答案强调：CGI 程序在子进程中运行，子进程终止时，内核会关闭其所有描述符。它不必像长期运行的服务器一样，靠反复显式关闭输入输出流来回收每次请求的资源。上面的代码先刷新输出，再正常退出；不能据此推断标准 I/O 在所有网络程序中都安全。
%%% option: A
处理完请求后子进程终止，其资源被回收，内核会关闭该进程仍打开的描述符。
%%% option: B
标准 I/O 库会自动把网络套接字转换为无缓冲模式。
%%% option: C
CGI 的标准输入输出并不对应文件描述符。
%%% option: D
标准 I/O 库会在每次写入后自动关闭流。
