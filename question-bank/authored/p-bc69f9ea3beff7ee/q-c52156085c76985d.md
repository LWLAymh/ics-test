%%% stem
20. 按教材线程交错模型分析如下代码：共享int读写各为原子动作，信号量正确保护每次递增；`printf`对j的实参读取与实际输出之间允许被其他线程抢占，每次输出本身是一整行。这里分析给定交错模型，不将存在数据竞争的程序视作严格ISO C下行为有定义的生产程序。
```c
sem_t s;
void *justdoit(void *arg);
int main()
{
    int i;
    pthread_t tids[3];
    sem_init(&s, 0, 1);
    for (i=0; i <3; i++) {
        pthread_create(&tids[i], NULL, justdoit, NULL);
    }
    for (i=0; i <3; i++) {
        pthread_join(&tids[i], NULL);
    }
    return 0;
}
int j=0;
void *justdoit(void *arg)
{
    P(&s);
    j = j + 1;
    V(&s);
    printf("%d\n", j);
    return NULL;
}
```
  下列哪一个输出结果是不可能的？
%%% reference
答案：D。完成第三次受保护递增的线程读到j=3，并最终打印3，因此任何完整输出都至少有一个3；D没有3。A/B/C可以通过其他线程先读取较小值、暂缓输出，再在打印3前后输出该值来实现。信号量只保护递增，未把“读取实参到输出”整个动作包进临界区。

%%% option: B
（2，3，2）
%%% option: C
（3，3，2）
%%% option: D
（2，1，2）
