第五题（16分）
现有一个直接映射（Direct-mapped）的高速缓存（cache），其总容量为16字
节，每个高速缓存块（cache block）为 4 字节（`B=4Byte/block`）。Cache
的初始状态为空。

（1）经过如下地址访问序列后，请填写cache第2组（即Set 2，注：从0开
始编号）的状态。数据块用10进制表示，举例：`M[4-7]`表示地址4-7的数据。
地址序列全部为读访存, 每次读取2个字节，地址单位为字节。
（提示：一次访存可能访问多个高速缓存块。）
（6分，v/Tag/Block，每空2分）

| 访问 | 地址 |
| --- | --- |
| R | 0 [000000_{2}] |
| R | 1 [000001_{2}] |
| R | 7 [000111_{2}] |
| R | 4 [000100_{2}] |
| R | 0 [000000_{2}] |

| Set 2 | v | Tag | Block |
| --- | --- | --- | --- |
|  |  |  |  |

本次访存序列，共发生 {{blank:legacy-gap-0}} 次高速缓存缺失(miss)? （2分）
（提示：一次访存可能引发多次高速缓存缺失。）
%%% part-reference: q-271458572c646e53
答案：Set 2 的状态为 v=1、Tag=00、Block=M[8-11]；本次访存序列共发生 3 次高速缓存缺失(miss)。

考察内容：
本题考察当访问数据和 cache block 不对齐时，对缓存的影响。每次访问是 2
个字节，当数据对齐（即首地址是偶数），并且2字节数据都在同一个缓存块时，
仅一次缓存的访问即可返回数据。如果数据未对齐，并且跨越了两个缓存块时，会
发生两次缓存访问。例如上图（R 7），需要访问数据 `M[7-8]`，其中`M[7]`和`M[8]`
分别在两个缓存块，则发生了两次缓存操作（缺失），并且会将缓存Set 2中的数
据块填满。
%%% part-stem: q-93065bcb1bef9ed1
（2）接上题，高速缓存重新清空后，执行如下访问序列，同时包含读访存（R）
和写访存（W）操作，每次读/写 2 个字节，高速缓存采用 write back +
no-write-allocate的管理策略，其他配置不变。请填写访存后cache第1组
（Set 1）的状态。

| 访问 | 地址 | Set 1：v | `Tag` | `Block` |
| --- | --- | --- | --- | --- |
| R | 0 [000000_{2}] |  |  |  |
| R | 1 [000001_{2}] |  |  |  |
| W | 7 [000111_{2}] |  |  |  |
| R | 12 [001100_{2}] |  |  |  |
| R | 9 [001001_{2}] |  |  |  |

本次访存序列，共发生 {{blank:legacy-gap-0}} 次高速缓存命中（hit）？

> 接上题的条件：直接映射（Direct-mapped）的高速缓存，总容量 16 字节，每个高速缓存块 4 字节（`B=4Byte/block`），Cache 初始状态为空。
%%% part-reference: q-93065bcb1bef9ed1
答案：
- 空①（Set 1 的状态）：**v = 0**，`Tag`、`Block` 均无数值（留空）—— 即 Set 1 始终没有被填入。
- 空②（命中次数）：**1** 次。

解析：

1. 配置换算：`16 B ÷ 4 B = 4` 个块，直接映射 ⇒ 4 组（Set 0–3）。地址划分（每次访问 2 字节，字节地址）：
   - 块内偏移 = 地址第 [1:0] 位；
   - 组索引 = 块号 mod 4 = 地址第 **[3:2]** 位；
   - `Tag` = 地址第 [5:4] 位。
2. 一次 2 字节访存可能跨两个块（题目提示过），逐条分析：

| 访问 | 涉及的字节 | 所在块（组） | 结果 |
| --- | --- | --- | --- |
| R 0 | 0–1 | 块 0–3（Set 0） | 冷启动不命中 → 装入 Set 0：`v=1, Tag=00, M[0-3]` |
| R 1 | 1–2 | 块 0–3（Set 0） | **命中**（数据已在 Set 0） |
| W 7 | 7–8 | 块 4–7（Set 1）+ 块 8–11（Set 2） | 写不命中；no-write-allocate ⇒ **不分配**，Set 1、Set 2 都不变 |
| R 12 | 12–13 | 块 12–15（Set 3） | 不命中 → 装入 Set 3：`v=1, Tag=00, M[12-15]` |
| R 9 | 9–10 | 块 8–11（Set 2） | 不命中 → 装入 Set 2：`v=1, Tag=00, M[8-11]` |

3. 唯一涉及 Set 1 的访存是 W 7（它覆盖字节 7–8，其中字节 7 属于 Set 1 的块 4–7）。写不命中 + **no-write-allocate**（写不分配）⇒ 该块不会进入 cache，所以 Set 1 保持初始的无效状态：**v = 0，`Tag` 与 `Block` 不填**。原卷评分说明也写着「v 是 0 即给 2 分」。反过来，如果策略是 write-allocate，Set 1 会被填成 `v=1, Tag=00, Block=M[4-7]`——这正是本题设的陷阱。
4. 命中次数：5 条访存中只有 R 1 命中（R 0 冷启动不命中、W 7 写不命中且不分配、R 12 与 R 9 也都是冷启动不命中）⇒ **共 1 次命中**。（官方评分材料另列了一套「第二套」计法得 5 次命中，并注明那套只给一半分；应以上面的 1 次为准。）
5. 注意 W 7 的另一半落在 Set 2：它同样因为 no-write-allocate 而不分配；随后 R 9 访问 Set 2 时才以「冷启动不命中」把它填上（`Tag=00, M[8-11]`），与 W 7 是否发生无关。

> 📌 答案有官方来源：原卷红色参考答案 + 批注（见 `_audit/pages/期中/2020期中-带答案/page-15.png`：Set 1 的 v 填红色 0、Tag/Block 留空；批注为「本题考察 no-write-allocate，写操作（W 7）不会将数据填写到 Set 1 中」，命中次数 1 次出自「第一套」答案）。解析由 AI 整理（deepseek v4.1 flash · 大肥鱼小姐）。

（3）为了提升高速缓存的效率，设计师提出两种修改方案
a)  将高速缓存块增大到 8 字节（`B=8Byte/block`），其他配置不变，每次
访存命中（hit）的时间开销为4个时钟周期；
b)  将高速缓存变为全相连（fully-associative，即`S=1`），其他配置不
变，每次访存命中（hit）的时间开销为2个时钟周期；
对于如下访问序列，分别采用两种修改方案的访存时间总开销相等，请问每次
高速缓存缺失（miss）的时间开销是{{blank:legacy-gap-0}}时钟周期？（给 4
分）
访问序列：

| 访问 | 地址 |
| --- | --- |
| R | 0 [000000_{2}] |
| R | 1 [000001_{2}] |
| R | 7 [000111_{2}] |
| R | 8 [001000_{2}] |
| R | 9 [001001_{2}] |

提示：修改高速缓存配置不会影响高速缓存缺失的时间开销
%%% part-reference: q-be2aa45e9dbbafe7
原卷评分说明列有两套答案口径，并要求“命中次数”和“缺失开销”两空匹配：

- 第一套：命中 1 次；方案 a 有 2 次缺失、4 次命中，方案 b 有 3 次缺失、3 次命中。令缺失开销为 $m$，则 $2m + 4 \times 4 = 3m + 2 \times 3$，得 $m=10$。若将每次缺失的访问时间也计作一次命中，则两方案各有 6 次命中，得 $m=12$。
- 第二套：把每次 2 字节访存都按两次缓存操作计算，命中 5 次，缺失开销为 18 或 20；原卷注明这套答案只给一半分。

来源：原卷第 15–16 页的红色评分说明；原卷未标明为何同时保留两套口径。
