第四题（10分）
使用Linux x86-64 LP64、GCC `-fcommon`、无LTO的传统公共符号模型，头文件已补齐。两个源文件的 `table` 类型冲突故意保留，作为第3问的分析对象；这里不将教材称作weak的COMMON与ELF `STB_WEAK` 混淆。

考虑如下两个程序（`fact1.c`和`fact2.c`）：

```c
/* fact1.c */
#include <stdio.h>
#include <stdlib.h>
#define MAXNUM 12
int table[MAXNUM];
int fact(int n);
int main(int argc, char **argv) {
    int n;
    table[0] = 0;
    table[1] = 1;
    if (argc == 1) {
        printf("Error: missing argument\n");
        exit(0);
    }
    argv++;
    if (sscanf(*argv, "%d", &n) != 1 || n < 0 || n >= MAXNUM) {
        printf("Error: %s not an int or out of range\n", *argv);
        exit(0);
    }
    printf("fact(%d) = %d\n", n, fact(n));
}
```

```c
/* fact2.c */
int* table;
int fact(int n) {
    static int num = 2;
    if (n >= num) {
        int i = num;
        while (i <= n) {
            table[i] = table[i-1] * i;
            i++;
        }
        num = i;
    }
    return table[n];
}
```

（3）不能保证正确执行，两处同名 `table` 的类型不兼容：`fact1` 把它当 `int[12]`，`fact2` 却把相同存储位置的内容当成 `int *`。`main` 初始化头两个数组元素后，`fact2` 会将这些整数字节解释成指针并解引用，具有未定义行为，常见结果为段错误，但不保证任何环境下都以同一种方式失败。

原解析“链接器任意选一个weak、可能只留4字节”不符合此处GNU COMMON合并规则：不同尺寸COMMON合并采用最大尺寸，因此数组占48字节，LP64指针占8字节，最终仍会分配48字节。空间足够并不能消除数组/指针类型解释冲突。函数声明 `fact` 是未定义引用，也不是弱变量。参见 [GNU ld的COMMON合并规则](https://sourceware.org/binutils/docs/ld/Options.html#index-_002d_002dwarn_002dcommon)。
