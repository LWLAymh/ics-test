%%% stem
4. 关于浮点数，以下说法正确的是：

本题采用 IEEE 754 浮点运算，按“舍入到最近值，恰好居中时取偶数”舍入，不使用扩展精度。A、D 中的 `a`、`b`、`x` 必须使用**同一种浮点格式**，两边的加法也在该格式下完成，不允许混合 `float` 与 `double` 类型。B、C 比较的是同一计算过程分别采用高、低精度时的结果。
%%% reference
答案：D。

A 不成立，即使都是有限值，也可能因为舍入使严格不等式变为相等。例如采用 binary32 时，`a = 1.0f`、`b = 0.0f`、`x = 16777216.0f`，有 `a > b`，但两个加法结果都为 `16777216.0f`。

D 在题面规定的同格式、同舍入方式下成立：浮点加法保持非严格单调性，因此 `a <= b` 时不会得到 `a + x > b + x`；若 `a` 或 `b` 为 NaN，对应的和仍为 NaN，`>` 比较也为假。无穷大引起 NaN 时同样不会令 `>` 为真。

这里的“同一种浮点格式”不可省略。例如 `double a = 16777216.0; float b = 16777216.0f, x = 1.0f;`，`a > b` 为假，但左侧加法在双精度下得到 `16777217.0`，右侧加法在单精度下舍入为 `16777216.0f`，D 在混合类型下便不成立。

B、C 不成立：更高精度不能保证任意多步计算最终一定更接近精确值。例如计算 `(1 + 2^-53) - (1 + 3 * 2^-54)`，精确值为 `-2^-54`。binary32 中两个括号都舍入为 `1`，结果为 `0`，误差为 `2^-54`；binary64 中两个括号分别舍入为 `1` 和 `1 + 2^-52`，结果为 `-2^-52`，误差为 `3 * 2^-54`，反而更大。这个例子没有 NaN、Inf 或溢出。
%%% option: A
给定任意浮点数 `a`、`b` 和 `x`，如果 `a > b` 成立（求值为 `1`），则一定 `a + x > b + x` 成立。
%%% option: B
不考虑结果为 NaN、Inf 或运算过程发生溢出的情况，高精度浮点数一定得到比低精度浮点数更精确或相同的结果。
%%% option: C
不考虑输入为 NaN、Inf 的情况，高精度浮点数一定得到比低精度浮点数更精确或相同的结果。
%%% option: D
给定任意浮点数 `a`、`b` 和 `x`，如果 `a > b` 不成立（求值为 `0`），则一定 `a + x > b + x` 不成立。
