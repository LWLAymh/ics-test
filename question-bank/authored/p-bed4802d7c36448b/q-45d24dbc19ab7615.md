%%% stem
12.缓冲区溢出不仅会破坏返回地址，也有可能破坏局部变量。在 x86-64 架构、
LINUX操作系统下，对于给出的C代码和汇编代码，下列说法错误的是？
C 代码：
```c
int foo(char *s) {
    int a = 0x1;
    char c[4];
    strcpy(c, s);
    return a;
}

int main() {
    char s[8] = "01234567";
    printf("%x\n", foo(s));
    return 0;
}
```
汇编代码（`int foo(char *s)`，s in %rdi）：
```asm
foo:
  55                    push  %rbp
  48 89 e5              mov   %rsp,%rbp
  48 83 ec 20           sub   $0x20,%rsp
  48 89 7d e8           mov   %rdi,-0x18(%rbp)
  c7 45 fc 01 00 00 00  movl  $0x1,-0x4(%rbp)
  48 8b 55 e8           mov   -0x18(%rbp),%rdx
  48 8d 45 f8           lea   -0x8(%rbp),%rax
  48 89 d6              mov   %rdx,%rsi
  48 89 c7              mov   %rax,%rdi
  e8 cd fe ff ff        call  strcpy
  8b 45 fc              mov   -0x4(%rbp),%eax
  c9                    leave
  c3                    ret
```
%%% reference
答案：D
注意字符串结尾有‘\0’。

维护说明（暂停上线，以上为保留的原参考）：

- `char s[8] = "01234567";` 的 8 个位置全被字符占用，数组内没有 `\0`。将它作为 C 字符串传给 `strcpy` 会越界读取，题面没有给出后续内存，不能保证复制何时结束。
- 按所列汇编，`c` 从 `-0x8(%rbp)` 开始，局部变量 `a` 在 `-0x4(%rbp)`，保存的调用者 `%rbp` 在 `0(%rbp)`，返回地址在 `8(%rbp)`。即便额外假设第 9 个复制字节是 `\0`，它覆盖的也是保存的 `%rbp` 的最低字节，不是返回地址；不能用“字符串末尾有 NUL”证明 D 错误。
