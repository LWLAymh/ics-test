### Part A：虚拟内存（11分）

考虑如下小型系统：内存最小单位为 Byte，数据类型长度均为 Byte 的整数倍，采用小端法。页表项为 2 B，地址编码为 16 位，页大小为 128 B，使用一级页表。系统支持的虚拟地址空间为 8 KB，物理内存为 2 KB。TLB 为 8 组、每组 2 路（共 16 项），采用 LRU；TLB 单独储存，不占用物理内存。

系统运行一段时间后的 TLB 布局如下。每个 set 的两列分别表示一路，Tag、PPN 均以十六进制显示，Valid 为有效位。

| Set | 路 0 Tag | 路 0 PPN | Valid | 路 1 Tag | 路 1 PPN | Valid |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 0 | 2 | 6 | 1 | 5 | E | 0 |
| 1 | 0 | D | 0 | 3 | 7 | 1 |
| 2 | 1 | 3 | 1 | 5 | A | 1 |
| 3 | 6 | B | 0 | 4 | F | 1 |
| 4 | 0 | 8 | 1 | 7 | B | 1 |
| 5 | 5 | E | 0 | 2 | 4 | 0 |
| 6 | 1 | 4 | 0 | 0 | C | 1 |
| 7 | 3 | 8 | 0 | 6 | 0 | 0 |

页表前 16 项（VPN、PPN 为十六进制；无效项的 PPN 以 `-` 表示）：

| VPN | PPN | Valid | VPN | PPN | Valid |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 00 | - | 0 | 08 | - | 0 |
| 01 | - | 0 | 09 | E | 1 |
| 02 | - | 0 | 0A | 3 | 1 |
| 03 | 2 | 1 | 0B | - | 0 |
| 04 | 8 | 1 | 0C | 1 | 1 |
| 05 | - | 0 | 0D | - | 0 |
| 06 | C | 1 | 0E | D | 1 |
| 07 | - | 0 | 0F | 9 | 1 |

#### 1）

完整页表共有 {{blank:entries}} 个页表项；存储该页表需要 {{blank:table-pages}} 个物理页。（每空 1 分）

#### 2）

虚拟地址 `0x0721` 翻译得到的物理地址为 {{blank:physical-address}}（十六进制，如 `0x012`）。（2 分）

#### 3）

不考虑第 2 问对 TLB 和页表的修改，依次连续访问 `0x11A5, 0x1419, 0x1C01, 0x0863, 0x1C7F`。每次 TLB 未命中时将翻译结果的 PPN 替换入 TLB。假设过程中未发生缺页异常，共访问物理内存 {{blank:memory-accesses}} 次。不计指令地址的翻译和访问；不考虑高速缓存，每次物理内存访问均计 1 次。（3 分）

#### 5）

考虑 IA-32 两级页表系统：页表项为 4 B，地址编码为 32 位，页大小为 4 KB，每张页表占一页。一级页表基址为 `0x00E77000`。虚拟地址 `0x19260817` 对应的一级页表项地址为 {{blank:ia32-l1-pte}}。若该页表项值为 `0x0D000721`，则对应的二级页表项地址为 {{blank:ia32-l2-pte}}。（答案均用十六进制，每空 1 分）
%%% reference
1）64 项；64 × 2 B = 128 B，恰为 1 个 128 B 物理页。

2）`0x6A1`（也可写 `0x06A1`）。页内偏移为 `0x21`，VPN 为 `0x0E`，其有效页表项给出 PPN `0xD`，所以物理地址为 `0xD × 0x80 + 0x21 = 0x6A1`。

3）8 次。五次访问的 VPN 依次为 `0x23, 0x28, 0x38, 0x10, 0x38`，TLB set 依次为 3、0、0、0、0。第一次命中 set 3 中有效的 tag `4`；第二次在 set 0 的无效路填入 tag `5`；第三次 set 0 未命中，替换原有效 tag `2`；第四次对 tag `2` 未命中，按 LRU 替换第二次填入的 tag `5`；第五次命中第三次填入的 tag `7`。三次未命中各访问页表和数据，共 6 次，两个命中各访问数据一次，共 2 次。

4）B（缺页异常）；C（段错误）。`0x00D0` 的 VPN 为 1，其页表项无效；`0x2226` 超出系统配置的 8 KB 虚拟地址空间。

5）`0x00E77190`；`0x0D000980`。
