%%% stem
有的网络教材建议：与客户端交互前，在同一个已连接套接字描述符上打开两个标准 I/O 流，分别用于读和写：

```c
FILE *fpin, *fpout;

fpin = fdopen(sockfd, "r");
fpout = fdopen(sockfd, "w");
```

交互结束后：

```c
fclose(fpin);
fclose(fpout);
```

在基于线程的并发服务器中，这会导致致命的竞争条件。解释原因。
%%% reference
`fdopen` 不复制文件描述符，两个流拥有同一个整数描述符。第一次 `fclose` 已关闭底层套接字。此后另一线程的 `accept`/`open` 可能重用这个刚释放的描述符，第二次 `fclose` 就可能刷新到或关闭那个新连接。即使没有重用，第二次关闭也是对失效描述符操作。线程共享进程描述符表，所以这种窗口会伤及其他线程的连接。若要让两个流分别拥有描述符，应先 `dup` 并明确各自关闭所有权；仍需遵守标准 I/O 流的缓冲及协调规则。
