以下程序可能死锁。初始 `a=b=c=1`。`P` 获取锁，`V` 释放锁；每列按顺序执行，同一行不表示同时执行。

| 线程 1 | 线程 2 | 线程 3 |
| --- | --- | --- |
| `P(a);` | `P(c);` | `P(c);` |
| `P(b);` | `P(b);` | `V(c);` |
| `V(b);` | `V(b);` | `P(b);` |
| `P(c);` | `V(c);` | `P(a);` |
| `V(c);` | `P(a);` | `V(a);` |
| `V(a);` | `V(a);` | `V(b);` |

A. 列出每个线程会同时持有的每一对锁。

B. 若全局锁次序为 `a < b < c`，哪些线程违反加锁次序规则？

C. 为这些线程给出一个保证不死锁的新加锁次序。
%%% reference
A. 线程 1：`(a,b)`、`(a,c)`。线程 2：`(c,b)`。线程 3：`(b,a)`。线程 2 释放 c 后才请求 a，因此不会同时持有 `(c,a)`。

B. 线程 2（持 c 请求 b）与线程 3（持 b 请求 a）违反 `a<b<c`；线程 1 符合。

C. 可以统一要求所有线程在嵌套持锁时按 `a<b<c` 的顺序获取：线程 1 保持原顺序；线程 2 的 b、c 临界区先获取 b 后获取 c，再释放二者，最后单独获取和释放 a；线程 3 先单独获取和释放 c，再先获取 a 后获取 b，完成后释放。只要改变次序时保持实际受保护工作的互斥要求，所有持锁等待边严格递增，便不可能形成环。

原程序的一条死锁路径是：线程 1 持有 a，线程 2 持有 c，线程 3 已释放 c 后持有 b；此时线程 1 等 b、线程 2 等 b、线程 3 等 a，构成循环等待。
