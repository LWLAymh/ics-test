%%% stem
预线程化并发 echo 服务器中，每个工作线程取出一个不同的已连接描述符 `connfd`，调用下面的 `echo_cnt`，返回后关闭连接。RIO 在独立 `rio_t` 上使用时是线程安全的。`echo_cnt` 是线程安全的吗？是可重入的吗？为什么？

```c
#include "csapp.h"

static int byte_cnt;
static sem_t mutex;

static void init_echo_cnt(void)
{
    Sem_init(&mutex, 0, 1);
    byte_cnt = 0;
}

void echo_cnt(int connfd)
{
    int n;
    char buf[MAXLINE];
    rio_t rio;
    static pthread_once_t once = PTHREAD_ONCE_INIT;

    Pthread_once(&once, init_echo_cnt);
    Rio_readinitb(&rio, connfd);
    while ((n = Rio_readlineb(&rio, buf, MAXLINE)) != 0) {
        P(&mutex);
        byte_cnt += n;
        printf("server received %d (%d total) bytes on fd %d\n",
               n, byte_cnt, connfd);
        V(&mutex);
        Rio_writen(connfd, buf, n);
    }
}
```
%%% reference
线程安全，但按教材分类不可重入。`pthread_once` 确保初始化只执行一次；共享 `byte_cnt` 的读写由同一个互斥信号量保护；RIO 状态及缓冲区为每次调用独有。不可重入是因为函数依赖共享静态计数器及其互斥锁，需要同步才能安全执行，而不是每次调用完全独立。若同一线程在持锁时重入并试图再次取锁，还可能自身阻塞。
