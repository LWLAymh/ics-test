练习题 3.46 图 3-41 是一个函数的（不太好的）实现，这个函数从标准输入读入一行，将字符串复制到新分配的存储中，并返回一个指向结果的指针。

考虑下面这样的场景。调用过程 `get_line`，返回地址等于 `0x400076`，寄存器 `%rbx` 等于 `0x0123456789ABCDEF`。输入的字符串为“0123456789012345678901234”。程序会因为段错误（segmentation fault）而中止。运行 GDB，确定错误是在执行 `get_line` 的 `ret` 指令时发生的。

```c
/* This is very low-quality code.
   It is intended to illustrate bad programming practices.
   See Practice Problem 3.46. */
char *get_line()
{
    char buf[4];
    char *result;
    gets(buf);
    result = malloc(strlen(buf));
    strcpy(result, buf);
    return result;
}
```

%%% part-stem: q-0300000000000046-C
C. 程序应该试图返回到什么地址？

程序试图返回的地址是 {{blank:ret}}
%%% part-reference: q-0300000000000046-C
题源答案：**`0x040034`**。低位 2 字节被字符 ‘4’ 和结尾的空（null）字符覆盖了。

按题面给出的数值核算：字符串“0123456789012345678901234”有 25 个字符，`gets` 还会写入一个结尾的空字符，共 26 字节；缓冲区 `buf` 就在 `%rsp` 处（第 4 行 `mov %rsp,%rdi`），所以这 26 字节覆盖 `%rsp+0`～`%rsp+25`。第 2 行 `push %rbx` 压入的 `%rbx` 保存值占 `%rsp+16`～`%rsp+23`，返回地址占 `%rsp+24`～`%rsp+31`。于是返回地址 `0x400076` 的低 2 字节 `0x0076` 被 `0x34`（字符 ‘4’）和 `0x00`（空字符）覆盖，得到 `0x00400034`。题源把这一结果写作 `0x040034`（即 `0x40034`），比按题面数值核算出的 `0x00400034` 少写了一位 `0`。两种写法在此照录，空位判定同时接受 `0x040034`、`0x00400034`、`0x400034` 和 `0x0000000000400034`。
%%% part-stem: q-0300000000000046-D
D. 当 `get_line` 返回时，哪个（些）寄存器的值被破坏了？
%%% part-reference: q-0300000000000046-D
寄存器 `%rbx` 的保存值被设置为 `0x3332313039383736`。在 `get_line` 返回前，这个值会被加载回这个寄存器中。

同一来源答案的核算：`%rbx` 的保存值位于 `%rsp+16`～`%rsp+23`，被输入字符串第 17～24 个字符 `6`、`7`、`8`、`9`、`0`、`1`、`2`、`3` 覆盖，对应的字节是 `0x36`、`0x37`、`0x38`、`0x39`、`0x30`、`0x31`、`0x32`、`0x33`；按小端存放，这 8 字节组成的值就是 `0x3332313039383736`。函数返回前执行 `pop %rbx`，这个被破坏的值被装回 `%rbx`。
%%% part-stem: q-0300000000000046-E
E. 除了可能会缓冲区溢出以外，`get_line` 的代码还有哪两个错误？
%%% part-reference: q-0300000000000046-E
1. 对 `malloc` 的调用应该以 `strlen(buf) + 1` 作为它的参数（多出的 1 个字节用于存放字符串结尾的空字符）。
2. 代码还应该检查 `malloc` 的返回值是否为 `NULL`。
