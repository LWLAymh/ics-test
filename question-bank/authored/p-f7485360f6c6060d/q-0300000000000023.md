%%% stem
练习题 3.23 已知 C 代码如下：

```c
long dw_loop(long x) {
    long y = x*x;
    long *p = &x;
    long n = 2*x;
    do {
        x += y;
        (*p)++;
        n--;
    } while (n > 0);
    return x;
}
```

GCC 产生的汇编代码如下：

```asm
long dw_loop(long x)
x initially in %rdi

1  dw_loop:
2      movq  %rdi, %rax
3      movq  %rdi, %rcx
4      imulq %rdi, %rcx
5      leaq  (%rdi,%rdi), %rdx
6  .L2:
7      leaq  1(%rcx,%rax), %rax
8      subq  $1, %rdx
9      testq %rdx, %rdx
10     jg    .L2
11     rep; ret
```

编译循环产生的代码可能会很难分析，因为编译器对循环代码可以执行许多不同的优化，也因为可能很难把程序变量和寄存器匹配起来。这个特殊的例子展示了几个汇编代码不仅仅是 C 代码直接翻译的地方。各小问的答案分别列在对应小问的参考区。
%%% part-stem: q-0300000000000023-A
A. 哪些寄存器用来存放程序值 x、y 和 n？按汇编中的写法填写寄存器名，可带 `%` 也可不带。

| 程序值 | 寄存器 |
| --- | --- |
| x | {{blank:xr}} |
| y | {{blank:yr}} |
| n | {{blank:nr}} |
%%% part-reference: q-0300000000000023-A
虽然参数 x 通过寄存器 `%rdi` 传递给函数，可以看到一旦进入循环就再也没有引用过该寄存器了。相反，我们看到第 2～5 行上寄存器 `%rax`、`%rcx` 和 `%rdx` 分别被初始化为 x、x*x 和 x+x。因此可以推断，这些寄存器包含着程序变量：x 在 `%rax`，y 在 `%rcx`，n 在 `%rdx`。
%%% part-stem: q-0300000000000023-B
B. 编译器如何消除对指针变量 p 和表达式 `(*p)++` 隐含的指针间接引用的需求？
%%% part-reference: q-0300000000000023-B
编译器认为指针 p 总是指向 x，因此表达式 `(*p)++` 就能够实现 x 加一。代码通过第 7 行的 `leaq` 指令，把这个加一和加 y 组合起来，一条 `leaq 1(%rcx,%rax), %rax` 就完成了 $x + y + 1$ 的计算。

C. 对汇编代码添加一些注释，描述程序的操作，类似于图 3-19c 中所示的那样。
%%% part-reference: q-0300000000000023-C
添加了注释的代码如下：

```asm
long dw_loop(long x)
x initially in %rdi
 1 dw_loop:
 2     movq  %rdi, %rax             Copy x to %rax
 3     movq  %rdi, %rcx
 4     imulq %rdi, %rcx             Compute y = x*x
 5     leaq  (%rdi,%rdi), %rdx      Compute n = 2*x
 6 .L2:                        loop:
 7     leaq  1(%rcx,%rax), %rax     Compute x += y + 1
 8     subq  $1, %rdx               Decrement n
 9     testq %rdx, %rdx             Test n
10     jg    .L2                    If > 0, goto loop
11     rep; ret                     Return
```
