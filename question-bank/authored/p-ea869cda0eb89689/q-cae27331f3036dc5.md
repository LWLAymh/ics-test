**Problem E -- The Hit or Miss Question (15 pts)**

Given a 32-bit Linux system that has a 2-way associative cache of size 128 bytes with 32 bytes
per block. Long longs are 8 bytes. For all parts, assume that table starts at address 0x0.

Each sample starts independently with an empty cache. Use write-allocate and LRU replacement, and count only the array writes; loop variables stay in registers. `int` is 4 bytes. Both samples traverse columns first (`j` outer, `i` inner).

Code sample 1:

```c
int i;
int j;
long long table[4][8];

for (j = 0; j < 8; j++) {
    for (i = 0; i < 4; i++) {
        table[i][j] = i + j;
    }
}
```

Code sample 2:

```c
int i;
int j;
int table[4][8];

for (j = 0; j < 8; j++) {
    for (i = 0; i < 4; i++) {
        table[i][j] = i + j;
    }
}
```

> 原卷第二段代码末尾印有 `table[j][i]?`，是未完成的批注，不是可执行语句；此处去除，保留题意对应的单次数组写入。

**A.** For code sample 1, fill each row's access results in column order 0 through 7. Use an eight-letter H/M string (H = hit, M = miss), optionally separated by single spaces.

| Array row i | Results for columns j=0…7 |
| --- | --- |
| 0 | {{blank:a-row0}} |
| 1 | {{blank:a-row1}} |
| 2 | {{blank:a-row2}} |
| 3 | {{blank:a-row3}} |

答案：A. 表中每次访问都是 miss（原卷红色参考答案全部为 M）：

| | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 0 | M | M | M | M | M | M | M | M |
| 1 | M | M | M | M | M | M | M | M |
| 2 | M | M | M | M | M | M | M | M |
| 3 | M | M | M | M | M | M | M | M |

`miss rate = 1`（100%）
%%% part-stem: q-75be8682bc238388
**B.** For code sample 2, fill each row's access results in column order 0 through 7, using the same eight-letter H/M format.

| Array row i | Results for columns j=0…7 |
| --- | --- |
| 0 | {{blank:b-row0}} |
| 1 | {{blank:b-row1}} |
| 2 | {{blank:b-row2}} |
| 3 | {{blank:b-row3}} |

Miss rate: {{blank:b-rate}} (fraction, decimal or percentage).
%%% part-reference: q-75be8682bc238388
答案：B 的 4×8 命中/缺失表 —— 第 0 列全为 M，第 1–7 列全为 H。

| | 0 | 1 | 2 | 3 | 4 | 5 | 6 | 7 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 0 | M | H | H | H | H | H | H | H |
| 1 | M | H | H | H | H | H | H | H |
| 2 | M | H | H | H | H | H | H | H |
| 3 | M | H | H | H | H | H | H | H |

miss rate = **1/8**（32 次访问中 4 次缺失）

解析：

1. 先把 cache 参数换算清楚：容量 128 B ÷ 块大小 `32 B = 4` 个块；2 路组相联 ⇒ 4 ÷ 2 = **2 组**（Set 0 / Set 1）。于是「块号的奇偶」就是组索引（组索引 = 块号 mod 2），块内偏移占低 5 位，剩下的高位是标记。
2. 本题的样例是 `int table[4][8]`（元素 4 字节）：一行 8 个 `int = 32` 字节，**正好等于一个 cache block**。所以整个数组 128 字节 = 4 个块，元素 `table[i][j]` 落在**块 i** 上；组索引 = `i mod 2`：第 0、2 行 → Set 0，第 1、3 行 → Set 1。每组只需要放 2 个块，恰好用满 2 路 —— 整个数组都能常驻 cache（这正是本题 C 部分所说「the entire array fits in the cache」）。
3. 访问次序是 `j` 外层、`i` 内层（列优先遍历），每次访问 `table[i][j]`：
   - `j=0`：依次访问 (0,0)(1,0)(2,0)(3,0)，落在块 0、1、2、3，cache 初始为空 ⇒ 4 次冷启动不命中，第 0 列 4 个格子全为 M；
   - `j=1`…7：每个 (i,j) 仍然落在块 `i`，而这些块在 `j=0` 时已经被取进 cache，且期间没有任何访问会把它们挤出（每组只用到 2 个块、2 路）⇒ 第 1–7 列全部为 H。
4. 缺失率 = 4 次缺失 ÷ 32 次访问 = 1/8。

> 对照 code sample 1（上一小题）：那时 `table` 是 `long long`，一行 64 字节 = 2 个块，`table[i][j]` 落在块 `2i + (j≥4 ? 1 : 0)`，于是 Set 0 要容纳块 0、2、4、6（4 个块）、Set 1 要容纳块 1、3、5、7（4 个块），而每组只有 2 路 ⇒ 每次访问都把上一个块冲突挤出，32 次访问**全部缺失**，缺失率 1。所以 C 部分说第二个样例更好：它只有冷启动不命中。
%%% part-stem: q-5e663c7d74390b87
**C.** One code sample performs better than the other. Why is this?
%%% part-reference: q-5e663c7d74390b87
答案：The second sample performs better than the first because it makes better use of the cache. In the first, heavy conflict results in a large number of evictions. In the second, the entire array fits in the cache, and the only misses are cold misses.
