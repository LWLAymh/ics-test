%%% stem
12. 现在有一个用户程序执行了如下调用序列
```
void *p1 = malloc(16);
void *p2 = malloc(32);
void *p3 = malloc(32);
void *p4 = malloc(48);
free(p2);
void *p5 = malloc(4);
free(p3);
void *p6 = malloc(56);
void *p7 = malloc(10);
```
内存分配器内部使用显式空闲链表实现，按照地址从低到高顺序来维护空
闲链表节点顺序。本题使用32位空闲链表指针：空闲块含4字节头部、两个各4字节的前后指针和4字节脚部，最小块为16字节；已分配块保留4字节头部和4字节脚部。每次请求按 `ceil((请求字节+8)/16)*16` 计算总块大小，余块不足16字节则不分割。这里“16字节对齐”指总块大小取16的倍数。分配算法采用首次适配算法，将适配到的空闲块的第一
部分作为分配块，剩余部分变成新的空闲块，并采用立即合并策略。假设初始
空闲块的大小是1KB。那么以上调用序列完成后，分配器管理的这1KB内存
区域中，按原卷口径将已分配块的头脚开销也计入“内部碎片”（即总已分配块字节减用户请求字节），其总大小是____，链表里第一个空闲块的大小是_____。
%%% reference
答案：D（来源：2019、2020期末-答案解析）
最终从低到高为：p1占32、p5占16、p6占64、空闲16、p4占64、p7占32、其余空闲800字节。已分配总量208，用户请求总量 `16+4+56+48+10=134`，按本题口径差74字节，其中40字节是五块的头脚开销、34字节是对齐浪费。首空闲块16字节。若采用64位空闲指针或不把头脚算入碎片，不能直接使用原答案；题面已补齐缺图对应的布局和计量定义。
