第八题（12分）第2问：假设有三个线程，已声明三个信号量 `s1`、`s2`、`s3`，初值分别为 `1`、`0`、`0`。将对应的 `P()` 和 `V()` 操作填入下面六个标号处，每处至多填写一个操作，也可留空，要求三个线程并发执行并全部结束后，结果只能是 `x = 10`。

按教材信号量交错模型作答：`x` 为共享整数，初值为 `1`；三个线程各执行一次，整数除法向零截断；`P(&s)` 等待正值后原子减一，`V(&s)` 原子加一并具有通常的同步语义。赋值的读、计算、写可以被抢占，不预设整条赋值原子化。假设信号量操作成功、可运行线程最终得到调度，方案必须使全部线程完成，不能靠死锁使错误结果不出现。

```c
x = 1;
void thread1(void) {
    /* ① */
    x = x * 5;
    /* ② */
}
void thread2(void) {
    /* ③ */
    x = x + 3;
    /* ④ */
}
void thread3(void) {
    /* ⑤ */
    x = x / 2;
    /* ⑥ */
}
```

请在同一答题框中按 `①…；②…；③…；④…；⑤…；⑥…` 给出完整方案，留空处写“空”，并简要说明为何任意允许的线程交错都得到 `10`，且不存在死锁。不得改动初值、三条赋值或增加标号外的操作。本题按整套方案评阅，合法方案不唯一。

以下给出两套合法方案，均满足每处至多一个操作；参考表不是逐空唯一答案。

| 位置 | 方案A | 方案B |
| --- | --- | --- |
| ① | `P(&s2)` | `P(&s3)` |
| ② | `V(&s3)` | 空 |
| ③ | `P(&s1)` | `P(&s1)` |
| ④ | `V(&s2)` | `V(&s2)` |
| ⑤ | `P(&s3)` | `P(&s2)` |
| ⑥ | 空 | `V(&s3)` |

方案A中，`s2=s3=0` 使线程1、3在各自赋值前等待。线程2由 `s1=1` 放行，完成 `x=1+3=4` 后才 `V(&s2)`；线程1取得该许可后完成 `x=4*5=20`，再 `V(&s3)`；线程3随后完成 `x=20/2=10`。因此三条赋值不重叠，顺序为线程2 → 线程1 → 线程3，即使赋值内部可被抢占也不会产生不同结果。

方案B中，线程1、3分别等待初值为零的 `s3`、`s2`。线程2先计算 `x=4`，再释放 `s2`；线程3计算 `x=4/2=2` 后释放 `s3`；线程1最后计算 `x=2*5=10`。顺序为线程2 → 线程3 → 线程1，同样正确。旧参考“执行顺序必须为2 → 1 → 3”的断言错误。

两套方案都由初始可运行的线程2启动，后继只等待前驱最终执行的 `V`，没有环形等待；在题定调度前提下全部线程都能结束。各相邻赋值之间还由对应 `V/P` 建立同步，不能只在假定赋值原子化的模型下验证方案。

在方案A或B中把③改为“空”也合法：线程2本来就是起点，后续两条赋值仍由 `s2/s3` 串接；不要求三个信号量都必须使用。其他合法方案也应接受，不能因为某个位置不同于上表而判错，也不能从两列分别任选操作拼成方案后直接认定正确。

整体评阅关键点：

1. 六处均明确给出操作或“空”，每处最多一个 `P(&s1)`、`V(&s1)`、`P(&s2)`、`V(&s2)`、`P(&s3)`、`V(&s3)`，不修改题定程序与初值。
2. 按整套协议分析初始可运行线程、每次许可的产生与消费，保证在所有允许交错下最终只能为 `10`。只举一条成功执行路径不够。
3. 同时确认完成性：不存在全部未结束线程都永久等待的状态，且共享 `x` 的访问获得足够同步。不能把“没有得到错误终值，因为根本未结束”视为正确。
4. 不把上述任一参考方案、`P(&s1)` 的使用或某一个固定线程顺序当作必要条件。仅就三条赋值串行执行而言，六种顺序 `123/132/213/231/312/321` 的终值分别为 `4/5/10/10/3/15`；两种顺序均可得到 `10`。若提交的协议允许更复杂的交错，应直接检验其全部交错，而不是仅靠这张串行结果表判分。
