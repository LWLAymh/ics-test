第四题（10分）
考虑以下三个文件：

`polygon.h`：
```c
struct Node {
    float pos[2];
    int marked;
    struct Node* next;
    struct Node* prev;
};
typedef struct Node node;

node* alloc();
void init();
void gc();
```

`main.c`（函数中部分内容折叠）：
```c
#include "polygon.h"

node* root_ptr;

int main() {
    node* p;
    init();
    p = alloc();
    root_ptr = p;
    ...
    gc();
    ...
    return 0;
}
```

`gc.c`（函数体被折叠）：
```c
#include "polygon.h"

#define N (1 << 20)

static node polygon[N];
static node* free_ptr;
static node* root_ptr;

void mark(node* v) { ... }
void sweep() { ... }
void gc() { ... }
void init() { ... }
node* alloc() { ... }
```
按教材传统ELF/common符号分类，用 `gcc -fcommon -o polygon main.c gc.c` 得到可执行文件。折叠的函数体不作未给出的行为假设；以下问潜在根指针绑定问题，不要求断言所有可能函数体都必然回收在用对象。

答案：main.c中root_ptr为全局COMMON（教材归为弱），init是全局外部引用、强弱不适用，main是全局强；gc.c的N为宏、无对应链接符号，polygon是局部static、强弱不适用，alloc为全局强。同名root_ptr不冲突，是因为gc.c的static对象仅内部可见。潜在错误是main更新的根与GC内部读取的根不是同一个对象；不能在函数体折叠的情况下断言内部根恒为NULL。
2. `main.c` 的全局 `root_ptr` 与 `gc.c` 的 `static node* root_ptr` 同名，但后者是 `static` 局部符号，不参与全局符号解析；`gc.c` 里对外可见的 init/alloc/gc/mark/sweep 都只定义一次，所以链接器不会报多重定义错误。
3. 若GC从gc.c的静态root_ptr开始标记，main对另一个全局root_ptr的更新不会传播过去，可能遗漏仍在使用的对象。稳妥修复是在gc.c改为 `extern node *root_ptr;`，仅在main.c保留一个定义，或用明确的参数/接口传入根。只去掉static而留下两个暂定定义依赖-fcommon，现代默认-fno-common可能导致重复定义错误。

| `main.c` | `init` | 全局（外部引用）| 非强非弱 |
| `main.c` | `main` | 全局 | 强 |
