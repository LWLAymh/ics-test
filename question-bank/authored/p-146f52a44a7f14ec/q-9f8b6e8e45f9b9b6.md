%%% stem
同事希望使用信号通知父进程对子进程事件计数。子进程每发生一个事件就发送信号，父进程处理函数令全局计数器加一。他运行以下测试时发现：子进程发送 5 个信号，父进程最后打印的 `counter` 却总是 2。解释程序的错误。

```c
#include "csapp.h"
int counter = 0;

void handler(int sig)
{
    counter++;
    sleep(1); /* Do some work in the handler */
    return;
}

int main()
{
    int i;

    Signal(SIGUSR2, handler);
    if (Fork() == 0) {
        for (i = 0; i < 5; i++) {
            Kill(getppid(), SIGUSR2);
            printf("sent SIGUSR2 to parent\n");
        }
        exit(0);
    }
    Wait(NULL);
    printf("counter=%d\n", counter);
    exit(0);
}
```
%%% reference
普通 Unix 信号不排队保存每次发生的次数。处理 `SIGUSR2` 时该信号通常被阻塞，待处理集合只记录“至少还有一个 SIGUSR2”。若余下四次发送都发生在第一次处理期间，它们合并成一个待处理信号，结果仅执行两次处理函数。不能用标准信号的到达次数可靠表示事件数；2 是题述调度下的现象，不是所有调度的保证。共享计数器的异步访问信号安全性也是应注意的问题，但将其改为 `volatile sig_atomic_t` 仍不能解决信号合并。
