# 2026-10-12 代码填空的空白判分

## 目的与边界

公开报告指出 foo(p+1) 因空格习惯被误判。先前已添加该别名，本轮将纯空白差异抽为可复用的词法比较，而非继续枚举空格组合。

- 修改判分器，不修改 Markdown 渲染器。
- 为 v5 normalize 新增可选 syntax 字段，旧规则不变；没有全库数据迁移、自动猜语言或批量重写题面。
- C token、AT&T 操作数、AT&T 单条指令分别显式启用。保留字符串内容、词界、运算符边界和指令分隔，拒绝不支持的输入。
- 不运行用户代码、不 eval、不代数化简；不同进制或等价表达式仍按人工核实的别名判分。

## 验证

新增正例覆盖空格、tab、C token 间换行、完整汇编与操作数；反例覆盖字符串空白/大小写、粘连标识符、分裂运算符、注释注入、缺失助记符分隔、拆开寄存器、合并指令、超长输入及未知规则。

契约测试验证字段为显式选项、C 必须区分大小写、必须允许首尾空白，并保留旧 exact 的行为。浏览器专项验证真实填空的绿色反馈与整题判分使用相同规则。

验证通过：61 项 Node 测试、21 项 Python 测试、1001 道源题的全量验证和站点构建。浏览器回归覆盖 1001 道题、1238 个题面单元、57 个图片资源；C 的 `x+y` / `x + y`、真实递归调用填空及 AT&T 单条指令空白变体均通过。包含 Tab 和操作数周围空格的两条汇编也由本机 GNU 汇编器成功汇编。

用法与限制详见 [v5 编写指导](QUESTION_AUTHORING_V5.md#代码填空的可选空白比较)。
