# v5 设计审查与迁移交付

## 为什么不是继续标为 v4.1

审查确认：v4.1 是未实现的设计稿，线上仍由 v3 `layout`、`interaction`、`presentation` 和多个兼容路径驱动，文档版本与实际版本脱节。v5 是有意的不兼容升级，人工文件、生成 JSON、前端、校验与 PDF 工具使用同一套接口。

| 发现的问题 | v5 处理 |
| --- | --- |
| 内容块会割裂一段 Markdown；空位无法安全嵌入代码、表格 | 保留完整 Markdown；填空由显式字面锚点定位 |
| 小问题型与 solution.kind 缺少联合约束 | Schema 对整题及小问都做题型—评分方式约束，另校验键引用 |
| 同一大题分散在模块中，运行时拼组可能漏问 | 一个完整题目对象，parts 有序内嵌；模块仅索引，不持有副本 |
| 旧 verified 容易被误认为“官方答案已确认” | 答案可用状态与出处分开；未知出处保持 unknown/null |
| 强制填写审核人会诱发虚构人工审核 | 标为 legacy-migration，审核人和日期不伪造；新人工发布另有要求 |
| 数值等价、近似误差与数制匹配不明确 | 暂只实现显式 exact 白名单或 self；不承诺尚未实现的规则 |
| complete 混淆“有答案”和“原卷完整” | paper.coverage 独立记录，迁移为 unknown，不虚构收录完整性 |
| 校验依赖缺失会静默跳过 | v5 强依赖 jsonschema；缺失、错误或生成漂移直接失败 |
| 旧答案/题面重复存储及 fallback 会重新猜边界 | 一道题一个 authored 文件；前端不再从参考答案解析选项字母 |

## 迁移边界与证据

基线提交为 `dffc49f7184a3448793568ea042cf7e7ba9ab21b`。

- `question-bank/migration/v3-baseline.json` 冻结全部 861 个旧片段的显式题面、选项、答案和评分配置。
- `id-map.json` 覆盖全部旧 ID，记录其新整题 ID 与小问 ID。已存在的独立题 ID、综合题 ID、试卷 ID 均保留；不根据文本重新计算。
- `decisions.json` 记录需要人工判断的结构修正及依据。当前仅一处：2021 期末第五题第 1 小问已有两个显式空位却标为简答，改为 fill，未猜逐空答案。
- `report.json` 是全量结构对照报告，包含基线 SHA-256 与未解决空位清单。
- `answer-provenance.json` 按既有 `AI_DERIVED_ANSWERS.md` 的 78 个明确文件登记保留 AI 出处和署名，不从答案正文猜测作者；其余旧答案来源仍为 unknown。

迁移只读取旧版已经明确的字段，完整复制 Markdown，不做去噪、自动代码围栏补全、数学变换、答案提取或单/多选猜测。迁移工具中保留的旧空位语法只用于**一次性冻结旧输入框的位置**，不会改题面，也不进入 v5 渲染器。旧 `_curated/` 和原始资料保留为追溯证据。

861 片段 → 738 完整题（含 56 综合题），28 份试卷；713 发布、25 待复核，已上线题目范围不因迁移缩小。逐项比对覆盖全部 Markdown 内容、选项顺序、空位、答案白名单、归一化规则和 ID/卷内关系。

## 已知债务，不以迁移掩盖

1. 25 道选择题的单/多选声明仍不明确，用 `unclassified-choice` 保留但不发布。
2. 37 个 fill 小问尚无可靠空位，显式登记 `blank-positions-unresolved`；保留 fill 类型，自评，不自动假造空位。此例外用于如实承接旧库，新题应补齐空位。
3. 旧答案的 `verified` 只迁移为可用，不建立 official 来源或人工复核事实。
4. 原 Markdown 中可能仍有内容或排版错误；字节不改写、结构全量验证不等于逐题核实原卷。
5. 选项 ID 限 A–H，与现有统计 RPC 一致。增加更多选项需同时升级 schema、前端和 SQL。
6. 综合题统计保持整题聚合，不新增小问数据库表。全部可评分小问等权合成，纯客观综合题也获得比例分；只有整题 1 分计为完全正确。
7. 迁移不删除或修改任何线上报告；修复了具体题后仍由维护者单独处理报告。

## 验证与后续维护

```powershell
npm run compile-bank
npm run verify-migration
npm run check
npm run build
```

`verify-migration` 必须在本次结构迁移交付时通过；后续人工正常改题会与基线不同，它不是长期日常 CI 门禁，更不能通过刷新基线掩盖改动。`check`、`build` 和分支 CI 是持续门禁。

`tests/browser-v5.cjs` 在真实浏览器中验证全库 Markdown/资源、整卷组题、各题型交互、同空同步、草稿恢复、计分、错误率排序及跳过。测试会替换 Supabase 客户端，不向线上提交任何统计或报告。启动本地 `_site` 服务后可用 Playwright 运行；Windows 可设置 `PLAYWRIGHT_CHANNEL=msedge`，其他平台使用已安装的 Chromium。

此分支不部署。等待维护者确认后才合并；主分支和线上仍保留原版本。若需要回退，在主分支继续使用基线提交即可，不需迁移数据库。后续 v5 编辑流程见 [完整编写指导](QUESTION_AUTHORING_V5.md)。
